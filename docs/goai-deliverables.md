# ArenaForge GOAI 交付清单

本文档只服务于 GOAI 赛道三·题目类型二（开放探索赛题）。
人大赛道、其他比赛和历史方案不属于当前交付主线。

## 1. 官方要求边界

根据 GOAI 官方赛道页面，题目类型二由参赛团队自行定义研究问题和系统方案。
初赛重点是让评审能够快速理解：

1. 你要解决什么问题；
2. 为什么这个问题值得解决；
3. 系统如何工作；
4. 评审如何访问和验证系统。

官方赛程和下载模板明确列出的初赛主交付物：

| 交付物 | 形式 | ArenaForge 对应物 |
|---|---|---|
| 问题定义文档 | 不超过 4 页 | `deliverables/goai/problem-definition.pdf` |
| 作品名称 | 提交表单必填 | ArenaForge 的最终参赛作品名 |
| 赛题 | 选择题目类型二 | `题目类型二：开放探索赛题` |
| 代码仓库 | GitHub 等可访问地址 | ArenaForge 公开仓库 |
| Demo 链接 | 可访问演示地址 | ArenaForge 在线 WebUI |
| 作品附件 | ZIP，必填 | `AI4R_OPEN_队伍名.zip` |

截至 2026 年 8 月 15 日，官方页面显示初赛材料提交截止时间为
2026 年 8 月 16 日 23:59。正式提交时以官方报名系统和下载的最新模板为准。

作品附件约束：

- 文件名必须为 `AI4R_OPEN_队伍名.zip`；
- 单个文件不超过 1200 MB；
- 本赛段附件累计不超过 3600 MB；
- ZIP 内必须包含问题定义文档和可核验的作品材料；
- 代码仓库和 Demo 链接不能只是空页面，必须能指向同一版本的作品。

初赛模板要求问题定义文档覆盖以下内容：

1. **问题与证据**
   - 真实问题或需求；
   - 为什么尚未被结构化；
   - 研究价值和合适切片。
2. **环境接口**
   - 固定规则；
   - Agent 的观察、行动和反馈；
   - 运行记录和资源预算。
3. **发现信号与参照**
   - 什么算发现；
   - 平凡解、随机探索、无干预参照；
   - 最低成功标准和失败标准。
4. **最小验证计划**
   - 第一次试跑的输入、步骤和输出；
   - 主要风险和失败路径；
   - 数据、依赖、运行、复现和开源计划。
5. **团队介绍**
   - 成员背景；
   - 团队分工；
   - 既有成果和作品链接。

初赛不强制提交源代码，但文档必须说明后续开源计划与边界。

官方赛道页面给出的后续交付物：

- 复赛：完整三件套；
- 决赛：决赛路演 PPT、现场 Demo、项目一页纸、答辩材料；
- GOAI DAY：继续进行决赛路演和现场 Demo。

官方公开页面没有在正文中展开“完整三件套”的全部文件命名。
ArenaForge 按以下工程内容准备：

1. 最小可运行环境或最终代码；
2. 技术文档、完整探索日志和探索结果；
3. 基线、对照实验和可复现说明。

如果下载的复赛手册或提交模板对文件名、压缩包结构、视频时长或大小有额外限制，
以该材料覆盖本文档。

官方核心作品要求还要求披露：

- 问题定义；
- 评测或发现信号；
- 数据来源；
- 依赖工具；
- 运行流程；
- 复现方式；
- 开源计划；
- 开放探索赛题的最小参照系和探索日志设计。

## 2. ArenaForge 要交付的成品

ArenaForge 提交的是一个围绕真实科学问题运行的开放探索系统。
Quantum Optics 是当前的 Reference Arena #1，用于展示通用运行时如何承载
真实物理模拟环境。

评审看到的主链路应当是：

```text
科学问题 + 可运行环境
    -> 环境扫描与协议生成
    -> AI 生成研究协议和候选方案
    -> 用户确认边界
    -> 多分支实验执行
    -> 指标比较、失败识别和证据记录
    -> 推荐方案、探索日志和可复现包
```

系统解决科研中的一个具体环节：

```text
研究问题
  -> B: 把问题变成可执行研究协议
  -> C: 生成并管理多个候选实验
  -> D: 在统一协议下运行、比较、保留证据
  -> E: 形成可复现的研究结论
```

ArenaForge 聚焦 B、C、D 三个环节：协议化、候选实验管理和统一执行取证。

- 分类、回归工程示例；

- 复现包和结果包 ZIP 导出；
- Markdown 报告渲染；

## 5. 现在的 GOAI 优先级

### P0：初赛材料

1. 选定一个真实科学问题作为 GOAI 主案例；
2. 定义该问题的最小参照系、发现信号和可验证成功判据；
3. 冻结 ArenaForge 的单句题目和一句话价值；
4. 完成不超过 4 页的问题定义 PDF；
5. 生成参赛摘要、系统链接和补充材料；
6. 把 WebUI 变成可访问的演示入口；
7. 生成一个干净的初赛附件包。

### P1：复赛能力证明

1. 使用真实 API 完成一次自主研究；
2. 保存完整的 hypothesis、代码 diff、命令、日志和指标；
3. 完成一次真实科学 reference arena 的可复现实验；分类/回归继续作为工程 smoke；
4. 在真实 SSH GPU 主机完成 smoke、恢复和结果回收；
5. 生成完整三件套和现场 Demo 版本。

### P2：决赛产品化

1. WebUI 从“运行查看器”提升为“输入研究目标的第一入口”；
2. 把 AI 生成协议、候选方案和执行计划串成一条明确流程；
3. 提供 API 配置页、运行状态页、证据页和导出页；
4. 预置离线 replay，保证没有 API 时仍可完整展示；
5. 让源码、运行产物、网页和视频中的名称、数字和结论完全一致。

## 6. 最终验收标准

ArenaForge 达到 GOAI 比赛级完成度，需要同时满足：

```text
评审输入一个真实科学问题的 reference arena 和研究目标
    -> 系统能解释它准备怎么研究
    -> AI 能提出至少两个候选方案
    -> 系统能在隔离分支中执行并比较
    -> 结果能追溯到代码、命令、日志和指标
    -> 系统能明确推荐、否定或暂不下结论
    -> 评审能导出并复现这次探索
```

GOAI 主演示以真实科学问题的 reference arena 为入口。Quantum Optics 是
ArenaForge 的第一个示例；ML 项目和其他科学环境可通过各自的协议接入。

只完成本地固定案例，不算最终完成；
只展示 UI，不算最终完成；
只展示模型对话，不算最终完成；
没有日志、基线、失败分支和复现包，也不算最终完成。
