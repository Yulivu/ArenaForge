# GOAI 题目类型二问题定义模板

> 这是提交前填写模板，不是最终报名文档。官方初赛模板明确要求由参赛团队自行完成问题定义，且禁止使用 AI 代写。ArenaForge 只提供结构、运行事实、图表数据和复现材料。

## 1. 真实问题与证据

### 1.1 问题名称

待参赛团队填写。

### 1.2 科学问题

待参赛团队用自己的语言填写一个可证伪的问题，避免写成“让系统分数更高”。

### 1.3 现实背景

说明：

- 该问题对应的科学对象或实验设计；
- 当前已有方法能做到什么；
- 为什么仍然存在结构化不足、搜索空间大或约束难以兼顾的问题；
- 本作品只承诺解决哪个最小切片。

### 1.4 价值与边界

说明：

- 若发现正信号，下一步科学工作是什么；
- 若没有发现正信号，负结果如何帮助排除一种直觉；
- 本作品不把模拟结果直接宣称为实验室结论。

## 2. 探索环境接口

### 2.1 固定规则

填写目标态、资源预算、损耗模型、可用工具、随机种子和停止条件。

### 2.2 Agent 观察

填写 Agent 每轮可以看到的候选结构、历史结果、预算、失败原因和约束状态。

### 2.3 Agent 行动

填写 Agent 可以改变的参数或结构，以及不允许改变的评估器、数据和规则。

### 2.4 反馈

填写每次行动返回的 fidelity、count rate、edge count、robust score、日志和错误。

## 3. 发现信号与最小参照系

### 3.1 发现信号

说明什么模式才算值得继续研究，例如：

- 在多个损耗水平下同时保持高 fidelity 和有效计数率；
- 某个稀疏化假设被多个 seed 一致支持；
- 一个常见直觉被随机或简单参照反驳。

### 3.2 参照系

至少说明：

- canonical baseline；
- 简单结构变化；
- 随机负对照；
- 统一损耗扫描和 seed 协议。

### 3.3 成功与失败标准

填写最低成功 margin、重复次数、允许的 inconclusive 条件和停止规则。

## 4. 最小验证计划

由参赛团队填写：

1. 第一次运行的输入；
2. 运行命令和资源；
3. 预期输出；
4. 主要风险；
5. 数据和代码来源；
6. 复现步骤；
7. 开源和许可证计划。

ArenaForge 已提供可运行的最小 reference arena、Campaign 证据和 ZIP 组织结构，参赛团队需要据此完成自己的科学叙述、团队介绍和最终 PDF。

## 5. 团队介绍

由参赛团队填写成员、分工、背景、成果和联系方式。
